## Bun и форматирование

- `packageManager: bun@1.4.4`, `engines.bun: >=1.4.4`, `.bun-version`, CI и оба Docker stages — 1.4.4.
- Единственный форматтер — встроенный `bun fmt` / `bun fmt --check`. Настройки перенесены в `[fmt]` bunfig.toml, .oxfmtrc.json удален, Zed использует внешний вызов Bun. oxlint сохранен как анализатор.
- oxfmt и его платформенные пакеты отсутствуют в package/lock. `bun fmt --doctor` подтверждает нативное форматирование без внешнего formatter.
- Форматирование мигрировало сортировку импортов/переносы в нескольких прочих файлах; отдельного изменения их поведения не выполнялось.
- Официальное основание: [Bun formatter](https://bun.com/docs/format); фактический CLI Bun 1.4.4 проверен через --help и --doctor.

## Повтор браузерной проверки

Playwright не добавлен в зависимости продукта. Пример подготовки отдельного инструмента:

```sh
mkdir -p /tmp/spider-viewer-browser-tools
cd /tmp/spider-viewer-browser-tools
bun init -y
bun add playwright
bunx playwright install chromium
```

Из корня приложения запускайте собранный сервер только с disposable test DATABASE_URL, `JWT_SECRET=spider-browser-test-secret-for-local-use`, `AUTH_COOKIE_SECURE=false`, `REDIS_URL=` и локальным PORT. Затем:

```sh
SPIDER_BROWSER_TOOLS=/tmp/spider-viewer-browser-tools \
APP_TEST_DATABASE_URL=postgresql://postgres:spider-test-only@127.0.0.1:32769/spider_test \
SPIDER_TEST_BASE_URL=http://127.0.0.1:4301 \
bun tasks/2026-10-25-fixes/browser-smoke.mjs
```

Замените адреса на порты собственной одноразовой БД/сервера. Runner создает синтетических пользователей и монтажный снимок; запускать на рабочей базе нельзя. Новая dev-зависимость fake-indexeddb нужна только для повторяемых unit-тестов браузерного API; Chromium и PostgreSQL дополняют ее проверками реальных платформ.

## Совместимость, восстановление и границы

Миграция схемы БД не нужна. Старые браузерные вкладки необходимо перезагрузить: submit требует userId, а утверждение pending — увиденную baseRevision; старый payload безопасно отклоняется до записи. Безвладельные legacy outbox и записи прежних снимков не удалены и не присвоены текущему пользователю; для их восстановления нужен явный выбор владельца/набора. После перехода SW v1 → v2 OCR-ресурсы потребуется подготовить заново для работы без сети.

Ревью выполнено отдельно по соответствию AC и по качеству кода: проверены серверные границы, параметры SQL, транзакции, повтор/авторство, пути ошибок, форматирование и CI. Это саморевью, не независимое ревью владельца. Внешняя защита веток и фактический запуск GitHub Actions не проверялись; CI-конфигурация подготовлена с отдельным PostgreSQL service.

Измерения тестов относятся к локальному Mac/Docker и синтетическим данным; они не являются production latency/SLO-профилем. Браузерный охват — Chromium; Safari/Firefox не проверялись. Исправления не публиковались и не разворачивались. Локальный откат — по diff этой задачи с сохранением прежних документов и пользовательского .gitignore; откат пользовательских данных не требуется, потому что рабочая БД не затрагивалась.
