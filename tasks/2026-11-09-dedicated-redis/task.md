# Отдельный Redis для Spider Viewer

Статус: завершено.

Источник: владелец уточнил, что ранее выбранный Redis принадлежит другому сервису, и потребовал создать новый. Исправляется ошибочная принадлежность, предположенная агентом. База f4d1086cccddc9ecdc1141813bec019173a43e98; существующие незакоммиченные артефакты tasks/2026-11-09-history-cleanup сохраняются. Код приложения не меняется.

## Критерии

- AC-01: создан новый самостоятельный Railway-сервис spider-viewer-redis в production проекта Spider Viewer с собственными credentials и постоянным volume.
- AC-02: только REDIS_URL Spider Viewer переключен на ссылку нового сервиса; повторно развернут прежний образ приложения, без изменений PostgreSQL/S3/других приложений.
- AC-03: из приложения подтверждены адрес нового сервиса, PONG и изолированный set/get/delete синтетического probe-ключа; health/readiness 200.
- AC-04: предыдущий Redis в этой задаче не изменяется; его ключи не переносятся, не удаляются и не читаются.

Риск: повышенный из-за новых credentials и требований изоляции; новая БД пуста, данные PostgreSQL не мигрируют и не удаляются. Проверки — реальные Railway metadata, конфигурация/endpoint без публикации секретов, PING и probe из приложения. При отказе подключения исправить новый сервис; не возвращать приложение к чужому Redis. Допустим временный REDIS_URL без подключения, если потребуется восстановление доступности приложения.

Поток: создание Redis из официального образа через Railway API → имя/volume/credential checks → app variable reference → redeploy прежнего образа → runtime checks. Неправильный project/service id блокирует mutation. Отсутствующий/неработающий Redis блокирует переключение. Работающие другие сервисы и чужая БД вне границ задачи. Новых зависимостей и прикладного diff нет; full build/test не проверяет эту операцию. Доказательства — completion.md.

Независимое read-only ревью runbook: /root/dedicated_redis_review. Блокеров нет; проверяются завершение старого app instance, точный новый host, NOAUTH и собственный volume.
