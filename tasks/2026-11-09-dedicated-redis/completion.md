У нового Redis отдельный случайный 256-битный пароль. Команда без авторизации вернула NOAUTH, с собственным паролем — PONG. Включен AOF. Публичный endpoint для Redis не создавался. Обезличенные значения и результаты — [evidence.json](evidence.json).

Во время rolling deployment первый probe попал в старый app instance и был остановлен защитой проверки hostname **до открытия Redis-соединения**. После SUCCESS и завершения старых app instances проверка нового endpoint выполнена успешно. Старое глобально кэшируемое Redis-соединение больше не существует, поскольку прежний app deployment не активен.

Создание выполнено через Railway API из официального Redis image с собственными variables/volume. Первоначальный CLI add не создал ресурсов из-за ошибки link; после проверки действующего доступа через API новый сервис создан явно в нужном project/environment. Это не меняло прежний Redis.
