# Сброс рабочего состояния: выполнено

Источник: уточнение владельца «Kanban, Общий прогресс, замечания, история ... всё осталось», [task.md](task.md). Исходная очистка истории работала: три audit/event-журнала были пустыми. Несоответствие заключалось в объеме операции — рабочее состояние намеренно сохранялось. Теперь добавлен явный `--reset-work-state`, и этот режим выполнен в production после нового бэкапа.

## Результат

- AC-01: удалены все 3 списка Kanban с 60 позициями/комментарием, все замечания и связи, 24 уведомления, старые статусы и история. Обнулен прогресс и снята старая атрибуция; 91 запись cable_progress удалена. Монтажный reset предусмотрен с увеличением revision, production-подсистема монтажа пуста.
- AC-02: совпали количество и хеши сохраняемых данных в 11 таблицах (для прогресса сравнивались неизменяемые атрибуты). Сохранены 11 аккаунтов, 4949 кабелей, 2 снимка, 11083 исходные строки и геометрия; S3-оригиналы не изменялись.
- AC-03: preview без записи, execute+maintenance обязательны. Приложение остановлено, deploymentStopped=true и нет других клиентов БД. Выполнены public write locks → snapshot → pg_dump18 → S3 → повторное скачивание/SHA-256 → reset одной транзакцией. CLI завершился кодом 0. Audit-кэш удален отдельно внутри **spider-viewer-redis**, без доступа к чужому Redis.
- AC-04: page-level queries `getActiveDashboardData` обоих режимов, `getRemarksData` и `getHistoryEntries` вернули 0% прогресса, пустые списки/замечания/историю. Все 13 очищаемых таблиц пусты; прогресс/его атрибуция обнулены. Приложение возобновлено прежним образом (deployment 6bd744b2-a533-438f-b838-ad7926c962af — SUCCESS); /healthz и /readyz вернули 200. Page-level queries повторно прошли после запуска.

Обезличенные числовые результаты, хеш проверенного исходного diff и ключ/контрольная сумма нового бэкапа: [evidence.json](evidence.json). База исходников `f4d1086cccddc9ecdc1141813bec019173a43e98`; hash в evidence — SHA-256 содержимого clear-history.ts + NUL + storage.test.ts. Существующие локальные документы предыдущих операций сохранены. Новые изменения — только режим сброса, его тест и документация; новых зависимостей/миграций нет.

## Ревью и восстановление

Независимое read-only ревью `/root/work_reset_review`: блокеров нет; область таблиц, FK, сохранение импортов/accounts и источники UI проверены. Неблокирующая формулировка ошибки после commit исправлена на Data cleanup committed, поскольку расширенный режим изменяет не только историю. Самопроверка требований и реализации проведена отдельно; реальные проверки состояния не заменялись мнением модели.

Для восстановления сохранен полный pre-reset dump в `backups/production/2026-11-09T17-39-50.579Z-f8722f87-4205-4153-816a-8704961f75ce.dump`, SHA-256 `0313e69a18eb018400b85d66a31c0877d1fb371728dfee7136a03ce83e2dd34d`. Восстановление — в новую БД по docs/storage.md; текущие данные соответствуют ожиданиям, поэтому восстановления не требовалось. Срок хранения — прежние 30 дней.

В shared preview открыта страница приложения, но профиль не авторизован и перенаправлен на login; tab закрыт. Авторизованный визуальный осмотр не заявляется.
