# Проверки Spider Viewer

Источник команд: `package.json`, `bunfig.toml`, `.github/workflows/ci.yml`, README. Рабочая директория — корень проекта. Воспроизведение: `bun install --frozen-lockfile`, затем перечисленные команды. Не использовать рабочую БД для тестов. `.env` не публиковать.

| ID   | Команда                                                 | Обязательность и успех                                                     | Граница                                                                      |
| ---- | ------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| V-01 | `bun run lint:check`                                    | CI: код 0                                                                  | oxlint и встроенный bun fmt, не поведение                                    |
| V-02 | `bun run test`                                          | CI: код 0; раскрыть skips/отсутствие тестов                                | Bun `test --check`, типы и happy-dom                                         |
| V-03 | `bun run build`                                         | CI: код 0                                                                  | OCR preparation + Vite сборка, не работа production                          |
| V-04 | `bun run typecheck`                                     | Дополнительная диагностика TS по затронутому коду                          | Не заменяет тесты                                                            |
| V-05 | `AUTH_TEST_DATABASE_URL=… bun run test`                 | Для изменений auth/БД применим реальный интеграционный прогон              | Только явно заданная disposable БД; без переменной auth-интеграции пропущены |
| V-07 | Проверка локальных Markdown-ссылок и `git diff --check` | Для текущего документационного подключения: отсутствие битых путей / код 0 | Не доказывает полноту ревью                                                  |

Владелец правил приемки — владелец репозитория. V-01–V-03 уже определены существующим CI; текущая задача не меняет их обязательность. Для добавления только Markdown обязательны V-07 и согласованность документов/матрицы; полный build приложения не является проверкой текстовых изменений. Для выпуска приложения существующие CI-проверки остаются обязательны.

Минимальная версия Bun — 1.4.4; packageManager, `.bun-version`, оба Docker stages и CI закреплены на 1.4.4, engines допускает >=1.4.4. Единственный форматтер — `bun fmt`; параметры в `bunfig.toml`, внешние форматтеры не нужны. Зависимости устанавливаются через `bun install --frozen-lockfile`.

Для регрессий БД сначала подготовьте отдельную disposable PostgreSQL с именем БД, содержащим `test`: `DATABASE_URL=postgresql://…/spider_test bun run db:push --force`. Затем `APP_TEST_DATABASE_URL=postgresql://…/spider_test bun run test:integration`. Тесты очищают данные только явно заданной тестовой БД, отказывают при совпадении с DATABASE_URL; рабочая БД не используется. Auth-интеграции используют AUTH_TEST_DATABASE_URL и изолированную схему. CI запускает оба набора на отдельном PostgreSQL service. fake-indexeddb — dev-зависимость для повторяемых тестов реального API очереди, не runtime-приложения.

Историческое состояние первоначального аудита и исходные сбои окружения сохранены в tasks/2026-10-25-review; новые результаты — tasks/2026-10-25-fixes/completion.md.

CI в репозитории есть, но обязательные статусы, защита веток и контролируемое намеренное падение в GitHub не проверялись. Автоматического runner для eval-сценариев нет; документальный разбор не считается фактическим прогоном.

Подробные результаты текущего аудита: `tasks/2026-10-25-review/completion.md`. Для будущего исправления дефекта сначала получить падающую регрессионную проверку по утвержденному поведению, затем повторить после правки и выполнить релевантный CI-набор.

Исторический reproduce.mjs описывает наличие дефектов в исходной ревизии и не является проверкой исправленного состояния. Для текущей версии используйте регрессионные тесты и test:integration.

Новые сценарии: `bun run test:integration` (F-02–F-07, F-10, F-12–F-13, реальная PostgreSQL); `bun run test` (IndexedDB, hook, Service Worker, OCR и SSR). Передачу сетевого запроса без сессии и полный офлайн-цикл дополнительно проверяет `tasks/2026-10-25-fixes/browser-smoke.mjs` в Chromium. Playwright для этого опционального прогона устанавливается вне зависимостей приложения; инструкция запуска — в completion.md задачи.
