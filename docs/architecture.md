# Карта архитектуры

Состояние обследования: `bee18d9`, 2026-10-25. Собственные модули перечислены по назначению; подробно исследованы серверные функции карты/монтажа, workflow, сохранение прогресса, офлайн-очередь и Service Worker. OCR и auth просмотрены по основным потокам. UI карты/формы, эксплуатационные скрипты и миграции изучены выборочно. Браузер и production-инфраструктура не проверялись.

Генерируемое: `src/routeTree.gen.ts`, `dist/`, `.tanstack/`, OCR assets. Сторонний код: `node_modules/`, Bun/npm зависимости. `.env` и `.private/` не являются источниками для публикации данных в отчетах.

Основные потоки:

1. Маршрут → createServerFn в `functions.ts` → guard (где подключен) → запросы/мутации → PostgreSQL → сериализованные view → UI. Проверка маршрута не заменяет guard серверной функции.
2. Workbook → FormData/валидация файла → Xlsx/parser → нормализация ключей → транзакция генеральных кабелей/снимка/агрегатов → dashboard.
3. Kanban → серверная проверка роли/этапа → изменение списка/позиций → task_events/notifications → router.invalidate. Некоторые эффекты выполняются вне основной транзакции.
4. Карта → draft прогресса → history.server → cable_progress/cables/audit в транзакции → Redis (таймаут 1.5 с) → обновление UI.
5. Монтаж → useInstallationBoard → online save с baseRevision либо IndexedDB outbox → submit offline → pending → apply group. Полная доска перечитывается каждые 15 секунд.
6. Фото → IndexedDB → Tesseract worker/canvas → кандидаты KKS → подтверждение → та же офлайн-очередь.
7. Service Worker перехватывает GET: fetch сети → общий Cache Storage → fallback из кэша при сетевой ошибке.

Границы доверия: cookies/JWT проверяются с актуальным пользователем БД; все входы клиента и workbook недоверенные. PostgreSQL и браузерные хранилища имеют разные сроки жизни и область авторства; повтор/гонка/смена аккаунта требуют явной обработки. Redis не должен препятствовать фиксации PostgreSQL. Схема и доступность реальных сервисов не подтверждены интеграционным прогоном.

## Изменения после аудита

Исправления 2026-10-25 описаны в `tasks/2026-10-25-fixes/completion.md`. Функции чтения проверяют сессию. Принятие карточки защищено условным UPDATE и транзакцией с событием; монтажные изменения используют атомарную проверку ревизии. Pending отображает текущие serverDone/serverRevision, утверждение проверяет увиденную ревизию. Импорт генеральных кабелей и обновление импортированного прогресса выполняются порциями по 500.

Офлайн-доска и очередь разделены по userId; отправка ограничена активным снимком и сверяет автора с сессией. Старые и безвладельные записи сохраняются локально и не отправляются под другим аккаунтом. Service Worker v2 кэширует ограниченный набор статических ресурсов (128 записей, 30 дней) и до 4 оболочек страниц текущего пользователя (24 часа); динамические server-function GET не кэшируются. Личные оболочки удаляются при смене пользователя/выходе. Сетевой статус начинает SSR/гидратацию одинаково, затем читает navigator.onLine в эффекте.

Форматтер — встроенный `bun fmt`; минимальная версия Bun 1.4.4, конфигурация в `bunfig.toml`. В CI добавлена отдельная PostgreSQL для auth/workflow интеграций. Настройки защиты веток остаются вне подтвержденного охвата.
